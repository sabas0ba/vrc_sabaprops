# 設計

VRChat ワールドから、アバターとワールドの表面へ液体の付着を描画するパッケージの設計です。
実装前の段階で方針と制約を固定するための文書であり、実装が進んだ時点で
「なぜ他の形にしなかったか」の記録へ書き換えていきます。

## 目的と位置づけ

アバターとワールドの**装飾**に限定したエフェクトです。水、塗料、泥、粘性の高い液体などが
表面に付着し、垂れ、乾き、洗い流される様子を、Projector を用いて描画します。

近年のアバターは高ポリゴン化し、シェーダ表現も多様になっています。本パッケージは
それらのアバターに対し、ワールド側から後付けで写実的な液体の付着を重ねることを目的とします。
重視するのは次の 2 点です。

- **写実性** — 濡れ、粘性による垂れ、乾燥、厚み、光沢の変化
- **インタラクティブ性** — かける・描く・拭き取る、水に浸かる・雨に濡れる・洗い流す

## スコープ

### 対象

- アバター（ローカル／リモート）表面への液体の付着描画
- 配置した範囲のワールド表面への液体の付着描画
- 液体の見た目をマテリアルとプロファイルで定義する仕組み
- 液体を付着させる、または除去する発生源（Source）
- 描画に必要な状態と操作のネットワーク同期

### 対象外

本パッケージは装飾のみを扱います。以下は実装しません。

- 勝敗、得点、塗布面積の集計など、ゲーム進行に関わる要素
- プレイヤーやチームへの色の割り当て。色は液体と Source の属性とする
- 付着状態に応じてプレイヤーの移動や表示を変える処理
- プレイヤーの移動制御全般（速度変更、滑走、沈下など）
- 付着を攻撃やダメージとして扱う処理
- 遮蔽物越しにプレイヤーを表示する描画
- 物理現象に対応しない振る舞い。液体の挙動はすべて重力、粘性、蒸発、凝結、洗浄など
  実在の現象を近似したものに限る

### 対象プラットフォーム

PC のみです。Android／iOS は対象としません。Projector は対象メッシュを追加描画するため、
モバイルでは予算に収まりません。

### Udon から利用できる API

公式文書に記載の無い範囲は、`.github/verify/vrchat/packages.lock` で固定した SDK 3.10.4 の
`VRC.Udon.Wrapper.dll` と `VRC.Udon.Graph.dll` に含まれる extern シグネチャで確認しました。

| API | 可否 | 設計への影響 |
|---|---|---|

| `new RenderTexture(...)`、`Create`、`Release` | 可 | Canvas の RenderTexture は実行時に確保できる |
| `VRCGraphics.Blit`（マテリアル指定を含む） | 可 | Canvas への書き込み手段とする |
| `Camera.Render`、`Camera.targetTexture` | 可 | 書き込み手段の代替 |
| `CustomRenderTexture` | 本体は可、`CustomRenderTextureUpdateZone` は構築不可 | 部分更新に使えないため採用しない |
| `VRCShader.PropertyToID`、`VRCShader.SetGlobal*` | 可 | 全 Canvas 共通の値（時刻など）の配布に使う |
| `ParticleSystem.GetCollisionEvents` | 不可 | パーティクルからは命中位置を得られない。位置は Raycast で求める |

## 全体構成

```
                 LiquidProfile（液体の定義）
                        │
                        v
 Source ──(場の評価 / 事象の評価)──> DrawOp（付着量・洗浄量）
                                        │
                                        v
                                 Canvas（RenderTexture）
                                        │ マスクとして参照
                                        v
                                 Canvas Projector ──> アバター / ワールド表面の追加描画
```

描画は必ず **Source → DrawOp → Canvas への書き込み → Projector による表示** の順で行います。
Source は DrawOp を生成するだけで、表示には直接触れません。

DrawOp は付着量と洗浄量の両方を持ちます。シャワーは水の付着と他の液体の洗浄を同時に行い、
タオルは洗浄のみを行う、というように、Source ごとに配分を変えます。

## Source

液体を扱うものはすべて Source として定義します。Source は次の 2 つの軸で分類します。

### 軸 A：出現の契機

| 区分 | 意味 |
|---|---|
| 常在 | ユーザーの操作なしにワールドに存在し、作用し続ける。多数配置されることを前提とする |
| 操作 | ユーザーの操作によって出現する、または作用する |

### 軸 B：作用の形態

| 形態 | 物理現象 | 付着のかかり方 |
|---|---|---|
| 浸漬 | 液体に浸かる | 液面より下に付着する。液面から出ると乾燥が始まる |
| 流下 | 連続した水流や散水 | 当たっている範囲に、時間あたりの量で付着と洗浄が進む |
| 降下 | 広い範囲に落ちる液滴 | 上を向いた面ほど多く付着する。遮蔽物の下では付着しない |
| 飛散 | 一度にまき散らされる | 命中点を中心に飛沫が付く |
| 接触 | 塗る、描く、拭く | 接触点の軌跡に沿って付着または除去する |
| 凝結 | 水蒸気が表面で水滴になる | 範囲内の表面全体に薄い水膜や細かい水滴が付く |

### 評価方式

軸 B から、Source の評価方式が 2 つに分かれます。

| 方式 | 形態 | 評価 |
|---|---|---|
| 場の評価 | 浸漬、流下、降下、凝結 | 時間あたりの量で連続的に作用する。Source の状態とプレイヤーの位置から、各クライアントが全プレイヤーについて独立に計算する |
| 事象の評価 | 飛散、接触、遠距離の流下 | 1 回ごとに位置と乱数を確定させる必要がある。Source の所有者が確定させ、DrawOp として配布する |

プレイヤーの位置とボーンは VRChat が同期しているため、場の評価に追加の通信は要りません。
Source の状態（放水の有無、姿勢、液面の高さなど）だけが同期の対象になります。

雨を液滴ごとの命中として送ると事象の評価になり、通信量が破綻します。降下は送らず、
各クライアントがサーバー時刻から決めた乱数で、受け手ごとに時間あたり一定数の雨粒の命中を
判定します。雪は命中を判定せず、「上向きの面への時間あたりの積雪量」として扱います。

水鉄砲は流下の一種ですが、命中位置が射線で一意に決まらず、所有者の入力に強く依存するため、
事象の評価とします。

### Source 一覧

| Source | 契機 | 形態 | 評価 | 同期する状態 |
|---|---|---|---|---|
| プール、浴槽 | 常在 | 浸漬 | 場 | なし |
| 海 | 常在 | 浸漬 | 場 | なし。液面の時間変化は共通の時刻から決定的に計算する |
| 水たまり、泥沼 | 常在 | 浸漬、踏み込み時の飛散 | 場 | なし。踏み込みの飛散は足元の速度から各クライアントで計算する |
| 雨、雪 | 常在 | 降下 | 場 | なし。降る周期と強さはサーバー時刻から決める |
| 水蒸気 | 常在 | 凝結 | 場 | なし。ワールド表面の曇りにも用いる |
| 固定シャワー | 常在または操作 | 流下 | 場 | 放水の有無 |
| 水道 | 操作 | 流下 | 場 | 蛇口の開度 |
| 可動シャワーヘッド | 操作 | 流下 | 場 | 放水の有無、姿勢（Object Sync） |
| 水鉄砲 | 操作 | 流下（遠距離） | 事象 | DrawOp |
| バケツ | 操作 | 飛散 | 事象 | 残量、DrawOp |
| 水風船 | 操作 | 飛散 | 事象 | DrawOp |
| 筆、ペン | 操作 | 接触（付着） | 事象 | DrawOp |
| 消しゴム、スポンジ、タオル | 操作 | 接触（除去） | 事象 | DrawOp |
| 自動散布（Sprayer） | 常在 | 飛散、流下 | 場 | なし。放つ時刻、首振り、ばらつきはサーバー時刻から決める |

消しゴム、スポンジ、タオルは液体を持たず、洗浄量のみを持つ Source として扱います。

自動散布は、飛散（一度に液体を放つ）を常在の Source として動かすものです。放つ時刻と方向を
サーバー時刻から決めるため、全クライアントが同じ時刻に同じ方向へ放ち、場の評価として扱えます。
噴水や滴りの演出と、操作しなくても液体の付き方が分かるデモに使います。

### マネキン

プレイヤーの代わりに液体を受ける固定の体です。Body Canvas を固定の Transform（マネキンの腰）に
追従させ、プールを介さず常に有効にします。命中判定は Canvas に設定したカプセルで行い、
Source はプレイヤーとマネキンを同じ規則で扱います（ターゲット番号：0 以上はプレイヤー ID、
-2 以下はマネキン）。

マネキンは専用のユーザーレイヤ（23）に描き、その Projector はそのレイヤだけに当てます。
プレイヤー用の Projector はアバターのレイヤ以外を無視するため、両者は互いの体に描きません。

### 常在 Source の多数配置

常在 Source は多数配置されることを前提とし、評価負荷を次の方法で抑えます。

- Source を空間グリッドに登録し、プレイヤーごとに近傍の Source のみを評価する
- 場の評価はプレイヤーごとに 5〜10 Hz で行い、Canvas への書き込みもその頻度でまとめる
- 降下と流下の遮蔽は頭上への Raycast で判定し、頻度を落としてフレーム間に分散させる
- 遠方のプレイヤーは評価頻度をさらに下げる

### 当たり判定

- 流下は、Source の放出方向に沿った光線とプレイヤーの体のカプセルとの交差で到達点を得る。
  パーティクルは見た目のみに用いる。Udon ではパーティクルの衝突位置を取得できないため
- プレイヤーの体は、足元から頭頂までのカプセルで近似する。半径と高さは目の高さに比例させる。
  Collider への Raycast を使わないのは、プレイヤーの Collider の構成に依存せず、
  ローカルとリモートを同じ規則で判定でき、Unity 無しで検査できるため。
  壁や屋根による遮蔽は、環境のレイヤへの Raycast で判定する
- 接触は Trigger と最寄り表面への Raycast で接触点を得る
- 浸漬は Source のボリュームと液面の高さから、Canvas に書き込む高さを得る
- アバターのボーンには Collider が無いため、到達点に最も近い Humanoid ボーンを
  `GetBonePosition` から求め、書き込み先の Canvas を決める

### 流下の付着

水は着いた点から体を伝って流れ落ちます。シャワーと水道は、着水点に飛沫を残すだけでなく、
着水点の高さより下を液膜で濡らし、同じ範囲の顔料を洗います。高さより下を扱う点は浸漬と
同じなので、Body Canvas の浸漬の仕組みをそのまま使います。

Canvas のテクセルからは高さを復元できないため、洗浄の範囲は次のように近似します。

- X 面と Z 面は、タイルの v がそのまま高さ
- Y 面は高さを持たないため、上面は頭や肩の高さ、下面は足裏の高さと見なす

### 降下（雨と雪）

`LiquidWeather` は、箱の範囲に雨または雪を降らせる常在の Source です。

- 範囲：Transform を中心とする箱。範囲内のプレイヤーとマネキンを評価する
- 遮蔽：受け手の頭上へ光線を伸ばし、遮蔽レイヤ（屋根、庇など）に当たれば降らない
- 周期：降る時間と止む時間をサーバー時刻から決め、降り始めと降り終わりで強さを徐々に変える。
  同期する状態は無い

雨は、受け手の頭上の円内から風の分だけ風上にずらした点を始点とし、時間あたりの粒数の光線で
命中を判定して、当たった所に小さく付けます。付いた雨は他の液と同じく流下し、乾きます。
粒の命中だけでは、降り続く雨で服が全体に濡れていく様子が出ないため、Canvas ごとに
上を向いた面の水の量を 1 つ持ち、降っている間は増やします。液体の定義を差し替えれば、
色の付いた液体を降らせることもできます（全体の濡れは水として描きます）。

雪は Canvas に書かず、Canvas ごとに積雪の深さを 1 つ持ちます。

- 降っている間は、時間あたりの量だけ深さが増える
- 止むと一定の速さで溶け、溶けた量が上を向いた面の水（雨と共通）になる。水は乾燥時間で減る
- Projector のシェーダは、受け手の法線が上を向くほど積雪を濃く描き、縁はノイズでむらにする。
  積雪の下の液は隠し、主光源の向きで細かいきらめきを加える
- 上を向いた面の水は、上を向いた面ほど多く残る液膜として描く

積雪を Canvas のテクセルに書かないのは、上を向いているかどうかが受け手の姿勢で変わるためです。
深さだけを持ち、向きは描画時の法線から決めると、回った後や腕を上げた後にも積もり方が
その姿勢に合います。代わりに、部位ごとに異なる深さは表せません。

地面は、`SabaProps/Liquid/Weather Surface` のマテリアルで描きます。濡れと積雪の度合いは
サーバー時刻の関数として求めてマテリアルに渡すため、途中から入ったプレイヤーにも同じ状態が
見えます。濡れると下地が暗く艶を帯び、ノイズの低い所から水たまりになります。雪は上を向いた面に
積もり、止むと溶けて濡れ、その後乾きます。地面には面ごとの遮蔽判定が無いため、屋根の下の面には
このマテリアルを使いません。

## 描画方式

### Projector の性質

設計を決める性質は次のとおりです。

- 投影範囲に入った Renderer を、Projector のマテリアルで**もう一度描画**する
- 対象の選別は Renderer の bounds 単位で行われる。アバターは全身が 1 つの
  SkinnedMeshRenderer であることが多いため、小さなデカールでも全身を再描画する
- 元のマテリアルのアルファを参照できない。カットアウトの板ポリゴンは矩形のまま描画される
- 投影方向の裏面にも描画される
- MaterialPropertyBlock を受け取れない。Projector ごとの値はマテリアルを分けて持つ
- Udon から Projector コンポーネントを操作できない。投影範囲は Editor で固定する

### Canvas への書き込み

Canvas は 2 種類の RenderTexture を持ちます。

| テクスチャ | 形式 | チャネル |
|---|---|---|
| 顔料 | ARGB32 | premultiplied の RGB と被覆率 |
| 液膜 | ARGBHalf | 液量、平滑度、粘性、蒸発率 |
| 奥行き | RGHalf | 付着した面の奥行き（m）、記録の確かさ |

液膜は蒸発で毎周期わずかに減るため、8 bit では 1 段階未満の減少が失われます。
そのため半精度にしています。

各テクスチャは 2 枚を交互に使い、`VRCGraphics.Blit` で前回の内容を読みながら
次の内容を書きます。1 回の Blit で次の処理をまとめて行います。

- 重力方向への流下。液量が多く粘性が低いほど流れ、筋状の揺らぎを持つ
- その周期に溜まった DrawOp の適用。DrawOp は `Material.SetVectorArray` で最大数を決めて渡す
- 液膜の蒸発。顔料は残る

書き込みは Canvas ごとに 5〜10 Hz とし、描画と同じ頻度では行いません。1 回の Blit の
コストは RenderTexture の解像度で決まり、DrawOp の数にはほぼ依存しません。

### 付着ごとに Projector を置かない

付着 1 つにつき Projector を 1 つ置く方式は採りません。上記の性質から、付着の数だけ
アバター全身が再描画されるためです。高ポリゴンのアバターほど負荷が線形に増えます。

代わりに、**RenderTexture を持つ少数の Projector（Canvas Projector）** を固定で配置し、
付着はすべてその RenderTexture への書き込みとして表現します。表示負荷は付着の数に依存せず、
Projector の数とアバターの描画コストだけで決まります。

### Canvas の種類

| Canvas | 追従先 | 数 | 役割 |
|---|---|---|---|
| Body | Hips | 1 人に 1 つ | 全身の付着、浸漬による付着 |
| Limb | 四肢・頭のボーン | 1 人あたり上限付き | 関節で大きく動く部位の付着の固定 |
| Surface | 固定 | 配置した数 | ワールド表面の付着 |

#### Body Canvas

体に固定した座標系に箱状の範囲を置きます。RenderTexture は 6 面（±X, ±Y, ±Z）の
アトラスとし、シェーダでは表面の法線を体の座標系へ変換して、各軸の表側の面を選びます。
面の境界は法線の重みで混合します。

これにより、単一方向の投影で起きる表裏の同一視を避けられます。

体の座標系は、ボーンの回転ではなく位置から組みます。Humanoid のボーンのローカル軸は
モデルの書き出し元によって異なるため、回転を使うとリグに依存するためです。

- 上：腰から胸へ向かう方向。寝転んだ姿勢にも追従する
- 右：左右の太腿の付け根を結ぶ方向を、上と直交させたもの
- 前：右と上の外積
- ボーンが無い場合：プレイヤーの向きで代替する

浸漬による付着（液面より下の濡れや泥）もこの Canvas で扱います。ただし RenderTexture には
焼き込まず、液膜と顔料それぞれの上端の高さをマテリアルに渡し、Projector のシェーダで
受け手の位置と比べて描きます。テクセルからは元の 3 次元の高さを復元できない一方、
シェーダでは受け手の位置が分かるためです。

- 液膜の上端は浸かった最高点を保ち、液から出ると粘性に応じて下がる
- 顔料の上端は下がらず、洗浄でのみ薄くなる
- 液面は水平でも体軸は傾くため、上端は体軸上で液面と交わる点で代表させる。
  体が大きく傾いている場合は全身か無しかで扱う

#### Limb Canvas

Body Canvas は Hips 基準なので、腕や脚を曲げると付着が表面上を滑って見えます。
関節で大きく動く部位の付着は、そのボーンに追従する Limb Canvas へ書き込みます。
Limb Canvas は付着が書き込まれた時点で有効化し、1 人あたりの上限を超える場合は
Body Canvas へ書き込みます。

#### Surface Canvas

ワールド側は、付着を許す範囲に Surface Canvas を明示的に配置します。
全表面を対象にしないことで、負荷と見た目の両方を配置者が管理できるようにします。
凝結による鏡やガラスの曇りも Surface Canvas で扱います。

### 描画対象レイヤ

アバター用の Canvas は Player、PlayerLocal、MirrorReflection 以外を `ignoreLayers` で除外します。
PlayerLocal と MirrorReflection を含めるのは、自分の身体と鏡像にも付着を描画するためです。

Projector の GameObject 自体は Player レイヤに置きます。カメラは、Projector が当たる先を見る前に、
Projector 自身のレイヤで Projector をカリングします。Default に置くと、Default を描かない
カメラから消えます。アバターだけを映すミラーは Player と MirrorReflection だけを描くため、
Default に置いた Projector の付着はミラーに映りません。

### 同じ向きの面の区別

6 面アトラスの 1 枚のタイルは、その面の向きを向いた表面のうち面内の座標が同じものを
すべて同じテクセルで表します。胴の側面と、その外側にある腕の側面は区別できず、
腕に付けた塗料が胴の側面や反対の腕の内側にも描かれます。

これを避けるため、付着を書くときに当たった面の奥行き（面の軸方向の Canvas ローカル座標）を
奥行きテクスチャへ記録し、描くときに受け手の奥行きと比べます。差が許容値以内なら描き、
その 2 倍を超えれば描きません。許容値の既定は 0.12 m です。

記録する奥行きは、命中判定のカプセル上の点の奥行きで、実際の体の表面とは一致しません。
許容値は、カプセルと体の表面のずれ（胴で 0.1 m 程度）が許容値の内側に収まるように取っています。
0.08 m ではカプセルが実際の頭より高い位置に当たった付着が描かれませんでした。
その代わり、胴の側面と腕の外側（0.2 m 程度離れる）の分離は完全ではなく、
写り込みは 3 割程度の濃さに抑えられる程度です。命中判定を体の形に近づけるほど、
許容値を小さくして分離を強められます。

1 テクセルに記録できる奥行きは 1 つです。同じテクセルに奥行きの異なる付着が重なると、
後から付いた方の奥行きが優先されます。

### Canvas の割り当て

Canvas は RenderTexture を 6 枚持つため、全員分を常に確保するとメモリが足りません。
Canvas Pool が、付着の入力を受けたプレイヤーにだけ Canvas を割り当てます。
空きが無い場合は、最も長く入力の無い Canvas を取り上げます。ローカルプレイヤーの
Canvas は取り上げの対象から外します。

割り当ては各クライアントが独立に決めます。同じプレイヤーでも、クライアントごとに
別の Canvas が割り当たることがありますが、見た目には影響しません。

## 液体プロファイル

液体の定義はプロファイル（UdonSharpBehaviour）とマテリアルの組で持ちます。
粘性を 1 つの値として持ち、シェーダ、パーティクル、付着形状の 3 箇所が同じ値を参照します。

| パラメータ | 意味 |
|---|---|
| 色、不透明度 | 付着の色。水は不透明度 0 で、濡れによる変化のみを描画する |
| 暗化量 | 表面が液体を含んだときの明度の低下 |
| 平滑度、反射強度 | 付着部の光沢 |
| 粘性 | 垂れの速度と長さ、飛沫の粒径、放出時の重力係数 |
| 厚み | 付着の縁の盛り上がりと陰影 |
| 乾燥時間、乾燥後の見た目 | 蒸発による消失、または乾いた色への遷移 |
| 洗浄性 | 水による洗い流されやすさ |

初期プリセットは次のとおりです。

| プリセット | 顔料 | 液膜 | 粘性 | 乾燥 | 洗浄 |
|---|---|---|---|---|---|
| 水 | なし | 多い、艶が強い | 低い | 90 秒 | 強い |
| ジュース | 薄い橙 | 多い | 低い | 120 秒、色が残る | 弱い |
| 塗料（赤、青） | 不透明 | 薄い、艶あり | 中 | 240 秒、色が残る | なし |
| 泥 | 濃い茶 | 厚い | 高い | 180 秒、明るく艶消しになる | なし |
| スライム | 半透明の緑 | 厚い、艶が最も強い | とても高い | 乾かない | なし |
| シロップ | 半透明の琥珀 | 厚い、艶が最も強い | 最も高い | 乾かない | なし |

プロファイルの色は、通常の色の項目と同じく sRGB で指定します。VRChat のワールドは
リニア色空間で描画されるため、Canvas に書く前にリニアへ変換します。配列で渡す値は
Unity が変換しないためです。

## 受け手の素材

同じ液でも、受け手の素材で見え方が変わります。

| 素材 | 見え方 |
|---|---|
| 柔らかい布 | 液を吸って暗く深い色になる。艶は少ない。塗料の縁が繊維に沿ってにじむ |
| 硬い布 | 一部を吸い、一部は表面ではじいて水滴になる。濡れると全体が艶を帯びる |
| 革 | 大半をはじいて水滴になる。濡れると艶が強い。塗料の縁が鋭い |
| 髪 | 硬い布や革に近い。液が上下方向の筋にまとまる |
| 肌 | 革に近いが、液は表面に留まって薄く広がり、流れ落ちにくい |
| 樹脂 | 吸わず、はじいて水滴になる |

素材は `LiquidSurfaceProfile` で表し、吸水性、撥水性、艶、流れにくさ、にじみ、毛束、
水滴の大きさを持ちます。

### 素材の割り当て

Projector は受け手の実際のマテリアルを読めないため、素材は位置から推定した部位ごとに与えます。

- 頭の球の中は髪。ただし顔の向き側で頭頂でない所は肌
- 手の球の中は肌
- 足の球の中は靴
- 腰から体の上方向に少し上がった面より下は下半身の衣服、上は上半身の衣服

頭、手、足の位置は、プレイヤーはボーン、マネキンは Transform から取り、半径は体格に比例させます。
部位ごとの素材は Canvas に設定し、プレイヤー用の Canvas は上半身を柔らかい布、下半身を硬い布、
靴を革、髪、肌としています。
推定は体の形からの近似で、肩より長い髪、手袋、顔を覆う装備などとは一致しません。
部位の推定を無効にすると、全身を衣服の素材で扱います。

### 描画への反映

- 暗化：吸水性が高いほど強い。撥水性の高い素材では、水滴の所だけが暗く沈む
- 艶：吸水性が高いほど弱く、素材の艶を下限とする。水滴の上は最も滑らか
- 水滴：撥水性の高い素材では、顔料の無い液膜を面ではなく水滴として描く。水滴は面内の
  格子ごとに乱数で置く球の断面で、液量が少ないほど小さく疎らになる。格子の並びが見えないよう、
  向きを変えた粗い層と細かい層を重ね、低周波の揺らぎで密度に粗密を付け、大きさは小さい方へ
  偏らせる。面内の重力方向へ伸ばし、下側を厚くする。法線を水滴の形に傾け、
  ハイライトと周りの映り込みを乗せる
- にじみ：顔料を周りの点と平均して縁をぼかす
- 毛束：液量と顔料を上下方向に伸ばした揺らぎで変調する
- 流れにくさ：衣服の素材の値で、Canvas の流下を遅くする。流下は Canvas 全体で計算するため、
  部位ごとには変えない

水滴、にじみ、毛束は、描画のたびに Canvas から計算する見た目で、Canvas には記録しません。

## シェーダ

- Projector 用シェーダを自作します（`unity_Projector` / `unity_ProjectorClip` を使用）
- 元の表面の見た目は変更できないため、濡れは乗算による暗化と、環境光（SH）の
  フレネル反射の加算で近似します
- Projector の描画パスにはライトの定数が設定されません。ワールドの主光源は
  `LiquidLighting` がグローバルなシェーダ定数（`_Udon_SabaLiquidLight*`）で渡し、
  シェーダは顔料の拡散光と、濡れた面の正規化 Blinn-Phong のハイライトを計算します。
  影は考慮しません
- 付着の厚み（顔料の被覆と、粘性で重み付けした液量）の勾配から法線を傾けます。
  塊や垂れが盛り上がって見え、ハイライトが縁に乗ります
- 顔料には粒状のむらを加え、広い面が一様な色で平板に見えるのを抑えます
- 垂れは Canvas の付着量を、Canvas 空間における重力方向へノイズ付きで引き伸ばして表現します。
  長さと速度は粘性と経過時間で決めます
- Projector の描画パスはアバターのノーマルマップを参照できないため、ジオメトリの法線を使います。
  高ポリゴンのアバターでは、この法線で十分な陰影が得られることを前提とします
- 屈折（GrabPass）は使いません

## 同期

同期するのは描画に必要なデータだけです。Canvas の RenderTexture 自体は同期しません。
各クライアントが同じ入力から同じ Canvas を再現します。

| 対象 | 方式 |
|---|---|
| 場の評価の Source | Source の状態のみを同期する。付着の結果は各クライアントで計算する |
| 事象の評価の Source（アバター宛て） | `[NetworkCallable]` で DrawOp を配布する。所有者が送信する |
| 事象の評価の Source（ワールド表面宛て） | 同上。加えて、途中参加者のために Manual sync の操作ログを持つ |

- DrawOp は「対象、Canvas、位置、法線、プロファイル、大きさ、乱数シード、付着量、洗浄量」を
  量子化して持ちます。乱数シードを含めることで、飛沫の形状を全クライアントで一致させます
- 連続する入力（放水、ペンの軌跡）は 5〜10 Hz でまとめて送り、既定の送信頻度を超えないようにします
- アバター宛ての命中位置は、対象プレイヤーの足元と水平の向きを基準にした座標で送ります。
  プレイヤーの位置はクライアントごとに少しずつ異なるため、ワールド座標で送ると
  受信側で体から外れた位置になるためです
- 受信側は、送り主がその Source の所有者であることを確かめてから付着を積みます
- 水鉄砲は同期変数を持たず、放水の開始と停止もイベントで送ります。使用ボタンのイベントを
  受けるには Pickup と VRCObjectSync のある GameObject に置く必要があり、そこで Manual sync を
  使うと VRCObjectSync と干渉するためです
- 場の評価の Source が光線の方向を作る乱数は、サーバー時刻から求めた評価周期の番号を
  種にします。当たり方がクライアント間でおおむねそろいます
- アバターの付着は途中参加者へ同期しません。リスポーンと退出で消去します
- 場の評価による付着は、クライアント間で厳密には一致しません。プレイヤー位置の同期遅延の範囲で
  ずれることを許容します
- ワールド表面の操作ログは Surface Canvas ごとのリングバッファとし、上限到達時は
  書き込みを止めるか、Canvas 全体を消去して再開します。古い操作だけを捨てると、
  既存の参加者と途中参加者で見た目が一致しなくなるためです

## 性能予算

- アバター用の追加描画は、1 人あたり「有効な Canvas Projector の数 × アバターのマテリアルスロット数」
- 距離による段階的な無効化を行う。一定距離以遠では Limb Canvas を止め、Body Canvas のみ残す
- ワールド全体で有効な Projector の上限を設ける
- 常在 Source の評価は、近傍探索と評価頻度で上限を設ける
- 利用者がローカル設定で本エフェクトを無効化できるようにする
- 具体的な数値は、高ポリゴンのアバターを含む計測で決める

## 検証方針

- 座標変換、Canvas の面選択、場の評価の計算、DrawOp の量子化と復元は、既存パッケージと同じく
  VRChat 依存を持たない部分クラスに分離し、`.github/verify/offline` で検査する
- シェーダの純粋関数は `.github/verify` のシェーダハーネスで検査する
- 同一の DrawOp 列から同一の Canvas が得られること（決定性）を検査する
- ClientSim と実環境で、ローカル／リモート／鏡像の描画と途中参加時の再構築を確認する
- デモのワールドを ClientSim で一定時間動かし、操作なしで全マネキンに付着が付くことを検査し、
  比較の列を撮った確認画像を出力する。見た目の調整はこの画像で行う
- 天候は、雨と雪を降らせ続けて、屋外のマネキンに付着と積雪があり、屋根の下のマネキンには
  無いこと、雪が止むと積雪が減って水が残ることを検査する
- 同梱したサンプルは、書き出したものをそのまま取り込んで参照が解決することを検査する
- 高ポリゴンのアバターを含む条件で、フレーム時間と Draw call を計測する

## 未確定事項

- Projector の投影範囲が Transform のスケールの影響を受けるか。受けない場合、Body Canvas の
  投影範囲は想定する最大の体格に合わせて固定する
- `OnPlayerParticleCollision` がどのクライアントで発火するか。命中位置は Raycast で求めるため、
  見た目のパーティクルとの整合のみに関わる
- Canvas の解像度とメモリ量。アトラスの面あたり解像度と、同時に存在する Canvas 数から決める。
  既定値（面あたり 160、12 Canvas）では 1 Canvas あたり約 4.9 MB、合計約 59 MB
- 主光源の影。LiquidLighting は向きと色だけを渡すため、屋内や日陰でも付着だけが
  主光源で照らされます。現状は intensityScale で弱める運用とする
- 浸漬で付いた泥が、液面の上下するデモで薄く見える。境界付近の見え方を調べる
- デモのシーンの大きさ。マネキンをプリミティブの組み合わせで置いているため、シーンが大きい。
  デモ（23 体）と比較（33 体）の 2 つのシーンに分けている。マネキンを Prefab にすると小さくできる
- デモのメモリ。マネキン 1 体の Canvas（面あたり 128）で約 3.1 MB を使い、デモで約 72 MB、
  比較で約 104 MB になる。実際のワールドでは、マネキンの数と解像度を用途に合わせて減らす
- 積雪は Canvas ごとに深さ 1 つで、部位ごとの差（肩に多く、腕に少ないなど）は法線の向きでしか
  表せない
- 地面の積雪と濡れは面ごとの遮蔽を持たない。屋根の下の面には天候のマテリアルを使わない運用とする
- プレイヤーの積雪と溶けた水は各クライアントで計算するため、途中から入ったプレイヤーには
  それまでの積雪が見えない。地面はサーバー時刻の関数のため一致する
- 水の付着は、艶のある素材の上では主に反射で見え、暗化は弱い。現実の傾向に近いが、
  デモとしての分かりやすさは実アバターで確認する
- アバターの拡大縮小への追従。Body Canvas の箱は固定寸法で、Projector の投影範囲も
  Editor で固定しているため、既定の箱に収まらない体格では箱の外に付着が描かれない
- 遮蔽判定の Raycast に用いるレイヤ構成

## 実装段階

1. Body Canvas、水と泥のプロファイル、浸漬（プール、水たまり）、流下（固定シャワー）、
   水鉄砲と DrawOp の同期
2. Limb Canvas、Surface Canvas、降下（雨）、凝結（水蒸気）、接触（筆、ペン、消しゴム、スポンジ、タオル）、
   飛散（バケツ）、塗料と高粘性液体
3. 可動シャワーヘッド、水道、水風船、ワールド表面の途中参加同期、
   距離による段階的な無効化、性能計測に基づく上限値の決定
