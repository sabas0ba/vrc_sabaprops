# Body Contact の設計

## 目的

プレイヤー同士のアバターが互いに貫通しないようにします。対象は PC VR と PC Desktop で、
World 単体で完結し、アバター側の対応を必要としません。

## World からできること

方式は VRChat の World API の制約で決まります。

| 操作 | 可否 |
| --- | --- |
| 他のプレイヤーのボーン位置の読み取り | 可能（`VRCPlayerApi.GetBonePosition`） |
| 他のプレイヤーのボーン・位置の書き換え | 不可 |
| ローカルプレイヤーの位置の変更 | 可能（`TeleportTo`、`SetVelocity`） |
| ローカルプレイヤーのボーンの書き換え | 不可 |
| VR の実際の手の位置の拘束 | 不可 |

動かせるのはローカルプレイヤーの体全体の位置だけです。したがって、自分の体のどこかが相手へ
侵入したら、侵入が解消する方向へ自分の体全体を動かします。VR では、相手へ手を押し込むと
自分が後ろへ下がり、手が相手の表面に留まります。

接触補正は全員が自分のクライアントで処理し、独自の同期を必要としません。結果の位置はVRChat標準のプレイヤー同期で伝わります。Grabによる引っ張りには、後述する保持状態の同期を追加します。

## 形状

相手側は 10 個の部位、自分側は 7 個の判定点で表します。寸法は目線の高さに比例します。

| 相手側の部位 | 形状 | 区分 |
| --- | --- | --- |
| 頭 | 球 | 体幹 |
| 体幹（Hips から Neck） | カプセル | 体幹 |
| 上腕・前腕（左右） | カプセル | 手足 |
| 大腿・下腿（左右） | カプセル | 手足 |

| 自分側の判定点 | 形状 | 区分 |
| --- | --- | --- |
| 頭・胸・腰 | 球 | 体幹 |
| 両手・両足 | 球 | 手足 |

判定は球とカプセルの距離計算で行い、Unity の Collider と物理クエリは使いません。計算が
引数だけで決まるため、Unity 無しで実行して検査できます。レイヤーや Collider の設定も不要です。

Humanoid でないアバターはボーンを取得できません。その場合は、プレイヤーの位置と目線の高さから
求めた標準体型で頭と体幹を代替し、手足は判定しません。

## 退く側の規則

双方のクライアントが同じ侵入を検出します。規則がなければ両者が同時に離れ、振動します。

| 自分の判定点 | 相手の部位 | 自分が退く割合 |
| --- | --- | --- |
| 手足 | 頭・体幹 | 1 |
| 頭・体幹 | 頭・体幹 | 動いている側ほど大きい。合計 1 |
| 頭・体幹 | 手足 | 0 |
| VR手足 | 手足 | 四肢接触が有効なら移動速度による分担。固定マネキンに対しては1 |

- 手足が相手の頭や体幹へ侵入した場合は、手足の持ち主が全量を退きます。相手は動きません。
  壁を押した場合と同じ扱いです。他人を押して動かすことを許さないための規則です
- 体幹同士は、自分の速度と相手の速度の比で負担を分けます。立ち止まっている相手へ歩いて
  入った場合は、歩いた側がほぼ全量を退きます。双方が静止していれば半分ずつです。
  双方が同じ式を評価するため、負担の合計は 1 になります
- VR手足から四肢への接触は `Limb Tolerance` 以下の侵入を許容し、深く侵入した部分だけ補正します。Grab中の保持手と対象者の四肢は除外します

Desktop の手足はアニメーションで動きます。待機モーションの腕振りで体が動かないよう、
Desktop では自分側の判定点を頭・胸・腰に限定します。

## 浅い侵入の許容

侵入量が `Tolerance` 以下の接触には応答しません。超過分だけを押し戻します。撫でる、握手する
といった動作で体が押し戻されると使い勝手を損なうためです。

## 通り抜けの許可

相手ごとに、接触判定が有効か、通り抜けを許可しているかの状態を持ちます。

- 判定範囲に入った時点で体幹同士が重なっていない相手は、有効で始まります
- スポーン、リスポーン、プレイヤーの入退室、`_Resume` の直後は、全員を通り抜け許可にします。
  最初から重なっている相手に弾き飛ばされないようにするためです
- 通り抜けを許可している相手は、体幹同士が離れた時点で有効に戻ります
- 有効な相手との体幹同士の接触が `Pass Through Seconds` 続くと、通り抜けを許可します。
  狭い通路で立ち止まった相手を通り抜けられるようにするためです

## 応答

1. 各接触について、相手の軸から自分の判定点へ向かう方向の水平成分を分離方向とします
2. 水平成分が小さい接触（ほぼ真上と真下）は扱いません。水平移動では解消できないためです
3. 複数の接触は、同じ向きの補正を二重に数えない方法で 1 つの分離ベクトルにまとめます
4. 分離ベクトルへ毎フレーム `1 - exp(-dt / Response Seconds)` を掛けた量だけ動かします。
   フレームレートによって硬さが変わりません
5. 1 フレームの移動量は `Max Speed` で制限します
6. 移動先に壁がある場合は移動を取り消します

移動には `TeleportTo` を `lerpOnRemote` 有効で使います。VRChat はこの指定を通常の移動として
扱い、リモートでの表示を補間し、アバターのアニメーションと IK をリセットしません。

## 遅延の影響

リモートプレイヤーの位置と姿勢は遅れて届きます。接触補正の応答は、相手がいると見えている
位置から離れる方向にしか働きません。引き寄せる項が無いため、古い位置を見て動いても、
離れすぎることはあっても、近づき直して往復することはありません。

体幹同士の負担の割合は、動く速さを決めるだけで、止まる位置は決めません。遅延がある場合、
各クライアントは相手も動いたことを知る前に、見えている侵入の全量を自分だけで解消し得ます。
その結果、双方が静止した状態で深く重なっていた場合に限り、必要な距離より余分に離れます。
余分な距離の上限は、最初の侵入量です。

通常の接近では、歩いている側がほぼ全量を負担し、侵入は浅いうちに解消されるため、この影響は
小さくなります。深い重なりから始まる状況（スポーン、テレポート）は、通り抜けの許可で
応答の対象から外しています。

オフラインの検査は、固定フレーム数の遅延を入れた 2 クライアントを互いに作用させ、
押し戻しの向きが反転しないことと、余分な距離が上限を超えないことを確認します。実際の
補間は固定遅延とは異なるため、最終的な確認は実クライアントで行います。

## 手・前腕の保持と水平追従

`BodyContactPull` は別の GameObject に配置し、Manual 同期で保持状態を共有します。
保持者・対象者の ID、左右の手と前腕、前腕上の保持位置、開始時の距離、開始時刻、
更新時刻を同期します。姿勢と位置は VRChat のプレイヤー情報から取得します。
1 システムにつき同時に 1 組、片手だけを扱います。

VR の保持者が相手の手・前腕付近で Grab を開始すると所有権を取得します。
対象者はローカルの許可が ON の場合だけ、自分の位置を移動します。許可は既定で OFF です。
拒否・解除時は対象者も所有権を取得して保持状態を終了できます。
保持中の第三者による所有権要求は拒否します。

開始距離と遊び幅を超えた水平距離から追従速度を求め、速度と加速度を制限します。
接触補正と逆向きの引っ張り成分を除去してから、システムの移動処理に渡します。
保持中は該当する手と相手の四肢の接触補正を除外します。体幹の接触補正は継続します。
壁判定には体幅の CapsuleCast を追加し、壁で停止した場合は追従速度をリセットします。

Grab を離す、Jump、解除ボタン、許可の取り消し、距離超過、更新期限切れ、退室、
リスポーン、参加者のアバター変更、体格変更、Station 着席で保持を解除します。
Station の停止は `BodyContactStationRelay` を World の Station に接続して伝えます。
アバター内の Station はこの接続処理の対象外です。

引っ張りには相手へ近づく応答があるため、接触補正だけの反転しない性質は適用できません。
通信遅延下の追従、所有権の競合、解除の伝達と視点の快適性は実クライアントで確認します。

## 検証の分担

| 対象 | 手段 |
| --- | --- |
| 判定規則、侵入量、分離ベクトルの合成、通り抜けの状態遷移、応答係数 | `.github/verify/offline/OfflineBodyContactTests.cs`。Unity 無しで実行 |
| VRChat SDK の API の呼び出し | `.github/verify/verify.sh`。実物の `VRCSDKBase.dll` に対してコンパイル |
| UdonSharp によるコンパイル | `.github/verify/vrchat/Tests/BodyContact`。実物の UdonSharp で実行 |
| 視点の動きの滑らかさ、リモートの遅延による振動、接触を伴う動作との両立 | 実クライアント。README の検証手順 |

ClientSim はローカルプレイヤーだけを生成し、`PostLateUpdate` を発火しません。そのため、
リモートプレイヤーとの接触は ClientSim では確認できません。

## 採用しなかった方式

| 方式 | 理由 |
| --- | --- |
| 相手ごとのカプセル Collider 1 個 | 手足の貫通を防げず、粒度が粗い |
| 全員を常時 Station に載せ、移動を Udon で再実装 | 標準の移動、ユーザーの快適性設定、ルームスケール追従を再現できない |
| 掴まれた側を一時的に Station に載せる | 乗降時の不連続と通知の遅延があり、貫通の抑制には過大 |
| 押された側を動かす | 迷惑行為に使える。押された側の視点が意図せず動く |
