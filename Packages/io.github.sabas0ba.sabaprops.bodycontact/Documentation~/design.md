# 設計

## 範囲

頭・体幹同士の侵入を検出し、ローカルプレイヤーの水平位置を補正します。
VRとDesktopは共通で頭・胸・腰の3点を使います。相手側は頭の球と体幹のカプセルです。
手足の接触補正、Grab、Pull、アバターの部位操作は対象外です。

各クライアントが自分だけを移動させます。独自の同期変数やネットワークイベントはありません。
相手の姿勢・位置はVRChat標準のプレイヤー情報から取得します。
四肢の幾何情報はマネキン外観と任意の参考表示に残します。
汎用の幾何ソルバーは判定点数を引数に取りますが、実行時は常にCoreProbeCount（3）を渡します。

## 接触と応答

- 各判定点と相手の頭・体幹の距離から侵入量を求め、Toleranceを差し引きます。
- 分離方向の水平成分が小さい接触は対象外です。
- 動いている側に大きい補正負担を割り当て、双方静止時は分担します。固定マネキンでは自分が全量を負担します。
- 複数の補正は同じ向きを二重に加算しないよう統合します。
- `1 - exp(-dt / ResponseSeconds)` で応答を平滑化し、最大速度を制限します。
- 移動先の膝・胸の高さで壁を判定し、衝突する補正を取り消します。
- 既定はTeleportTo（lerpOnRemote有効）です。SetVelocityは比較用に残します。

## 通り抜けと停止

スポーンなどで最初から重なっている相手は、離れるまで通り抜けを許可します。
有効な接触がPassThroughSeconds続いた場合も、離れるまで通り抜けを許可します。
手足だけの接触はこの時間に含めません。
手動停止とStation停止の状態を別々に保持します。Stationを降りても手動停止は解除しません。

## 診断と検証

Gizmoは20 Hz、HUDの頭部追従と接触処理は毎フレームで更新します。
表示・接触のローカル切替ボタンをサンプルに備えます。
マネキンは静止・壁際・小型・往復移動・旋回の5種類です。動作型はWorldで利用可能なAnimatorを使います。

オフライン検査は幾何計算と応答規則、Unity側はUdonコンパイルと生成シーンを扱います。
汎用ソルバーの手足を使う検査は内部計算の検査であり、実行時に手足補正を有効化するものではありません。
VRの視点、通信遅延下の静止接触、Stationとの連携は実クライアントで確認します。
今回の機能縮小後は、過去のテスト結果だけで動作を保証しません。
